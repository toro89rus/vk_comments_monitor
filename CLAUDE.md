# Правила для ИИ-агентов

Прочитай целиком перед любой работой. Если правило мешает задаче — остановись и спроси, не обходи его.

Проект — Telegram-бот (aiogram 3) и мониторинг комментариев VK, данные в Redis. Как он устроен — `ARCHITECTURE.md`:
прочитай его перед задачей. Если правка меняет структуру (новый или перенесённый модуль, хендлер, поток данных,
формат хранения в Redis), обнови `ARCHITECTURE.md` в том же коммите.

Известные баги и открытые вопросы — `docs/issues.md`, план рефакторинга — `docs/refactoring.md`. Перед задачей
проверь, нет ли там записи о коде, который правишь.

## Окружение и проверки

- Python 3.12, зависимости и запуск — только через `uv` (`uv sync`, `uv run ...`). `pip install` не использовать.
- Бот работает только на сервере через Docker Compose (`make run` — бот вместе с мониторингом VK).
  Локально не запускается, поэтому поведение проверяется тестами.
- Проверки перед коммитом:
  - `uv run ruff format` — форматирование;
  - `uv run ruff check` — без ошибок и предупреждений;
  - `uv run pytest` — все тесты проходят.
  Пока какой-то из этих инструментов не настроен — запусти то, что есть, и напиши в отчёте, чего не хватило.
- Тесты не ходят в сеть и в настоящий Redis: Redis — через `fakeredis`, Telegram и VK API — через подмену
  клиента или ответов.

## Коммиты

- Запрещено: force push, rebase и amend уже запушенных коммитов, удаление веток, переписывание истории.
- Один коммит — одно логическое изменение. Коммит «за несколько дней работы» запрещён.
- Сообщение — на английском, одной строкой: `<глагол> <что>`, с маленькой буквы, без точки в конце.
  Глагол — в повелительном наклонении, из списка:
  - `add` — новая функциональность, файл, модуль, тест;
  - `fix` — исправление бага;
  - `update` — доработка существующего без смены поведения по сути (логирование, формат, конфиг);
  - `change` — намеренное изменение поведения или формата;
  - `move` / `rename` — перенос или переименование без изменения логики;
  - `remove` — удаление кода, файлов, зависимостей;
  - `refactor` — рефакторинг без изменения поведения;
  - `revert` — откат коммита: `revert <hash>`.
- Область — по желанию, в скобках после глагола и с двоеточием: `fix(vk): handle petrovich Gender as string`.
  Области: `vk`, `tg`, `repo`, `config`, `migrations`, `tests`, `docker`.
- Примеры: `fix sending message to blocked user`, `add redis volume to compose`,
  `move vk_monitor update delay to env`, `refactor(tg): extract comment formatting to formatters`.
- Без `wip`, `quickfix`, `(hotfix)`, номеров багов вида `№2`: незаконченное не коммитить,
  повторное исправление описывать по сути.
- В `main` не пушить никогда: на сервере `deploy.sh` по крону подтягивает `main` и пересобирает контейнер,
  то есть пуш в `main` — это деплой. Работа — в отдельной ветке, в `main` попадает через ревью владельца.

## Качество кода

Правила — для нового и изменяемого кода. Старый код не переписывать ради них, а улучшать там, где всё равно правишь.

- Функция — до 60 строк (лучше до 40), цикломатическая сложность — до 15, вложенность блоков — до 4.
  Модуль — до 400 строк. Большой модуль целиком не переписывать: выносить связные куски по одному.
- Хендлеры aiogram — тонкие: разобрать апдейт, вызвать сервис, отправить ответ. Логика — в сервисах,
  доступ к Redis — в репозитории, форматирование текста — в форматтерах. Сервисы не зависят от aiogram-типов
  там, где без этого можно обойтись, — так их проще тестировать.
- Type hints — у всех новых и изменяемых функций (аргументы и возвращаемое значение). `Any` — только с причиной.
- Структуры данных — `dataclass` или модели, а не словари с договорными ключами.
- Async-код не блокирует цикл событий: никаких `requests`, `time.sleep`, синхронного Redis внутри `async def`.
  Для HTTP — `aiohttp` (уже есть через aiogram), для Redis — `redis.asyncio`.
- Без мёртвого кода: неиспользуемые переменные и импорты, `if False:`, закомментированные блоки — удалять.
- Ошибки не глотать: голый `except:`, `except Exception: pass` — только с комментарием, почему ошибку можно
  игнорировать. Иначе — обработка, запасной вариант или `logger.exception(...)`. Не `print` — только `logging`.
- Бизнес-значения — именованными константами или в конфиге: лимиты, таймауты, интервалы, ключи и префиксы Redis,
  ID чатов и групп.
- Конфигурация — только из переменных окружения через `tatd_bot/config`. Нигде больше не читать `os.environ`.
- Длину, сложность, вложенность и проглоченные исключения проверяет `ruff check` (`C901`, `PLR0912`, `PLR0915`,
  `PLR1702`, `BLE001`, `S110`, `ERA001`, `PLR2004`, `ASYNC`). Старые нарушения помечены `# noqa` поштучно.
  Новое нарушение чинить кодом, а не новым `# noqa`. Убрал старое нарушение — удали и его `# noqa`.

## Рефакторинг и тесты

- Рефакторинг — только когда поведение закреплено тестом, который проходит до и после. Нет теста — сначала
  напиши характеризационный тест на текущее поведение (даже если оно кажется странным), отдельным коммитом.
- Рефакторинг и изменение поведения — разными коммитами. В коммите рефакторинга поведение не меняется,
  тесты не правятся (кроме импортов при переносе модуля).
- Нашёл баг — не чини молча и попутно с другой задачей. Добавь запись в `docs/issues.md` (следующий номер,
  описание, где в коде, тест или «нет») и упомяни в отчёте. Тест, закрепляющий баг, помечай комментарием
  `# текущее поведение: …`.
- Исправление бага — отдельный коммит (`fix …`): тест с пометкой «текущее поведение» переписывается
  под правильное поведение, запись из `docs/issues.md` удаляется в том же коммите.
- Нашёл структурную проблему — запиши в `docs/refactoring.md`. Сделал пункт оттуда — удали его в том же
  коммите.
- Тесты — в `tests/`, структура повторяет `tatd_bot/`. Чистые функции (форматтеры, мапперы, склонение) —
  простыми юнит-тестами; сервисы — с `fakeredis` и подменёнными API-клиентами; async — через `pytest-asyncio`.
- Вынес кусок в модуль — добавь ему тест.
- Запрещено ради зелёных проверок: удалять или ослаблять тесты, глушить правила ruff массово, менять
  `ruff.toml` и настройки pytest без согласования.

## Данные в Redis

- Изменение формата хранения (ключи, структура значений) — только новой миграцией в `tatd_bot/vk/migrations/`
  со следующим номером. Уже существующие миграции не править.
- Миграция — с тестом на `fakeredis`: данные в старом формате → данные в новом. Повторный запуск не ломает данные.
- К боевому Redis не подключаться и миграции на нём не запускать — это делают люди.

## Запрещено

- Подключаться к серверам, деплоить и запускать `deploy.sh`, даже если доступ технически есть.
- Запускать бота или мониторинг с боевыми токенами: бот начнёт отвечать настоящим пользователям.
- Коммитить секреты: токены, пароли, `.env`, `vk_config.v2.json`, логи и дампы Redis.
- Захардкоживать токены, ID чатов и адреса — только через конфиг.
- Без согласования менять: `pyproject.toml` и `uv.lock` (новые зависимости), `ruff.toml`, `Dockerfile`,
  `docker-compose.yml`, `deploy.sh`, `Makefile`, этот файл.

## Отчёт после задачи

- хеши коммитов и одной строкой, что в каждом;
- как проверено (какие проверки запускались и с каким результатом);
- что не сделано или сделано не до конца, найденные по дороге баги;
- последней строкой: «CLAUDE.md прочитан на коммите `<git rev-parse --short HEAD>`».
