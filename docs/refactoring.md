# План рефакторинга

Здесь правки, которые не меняют поведение бота: тесты проходят до и после без изменений (кроме импортов
при переносе модулей). Баги и решения о поведении — в [issues.md](issues.md).

Шаги идут по порядку: каждый следующий опирается на предыдущие или становится проще после них. Один шаг —
один или несколько коммитов, каждый проходит `make check`. Сделанный шаг удаляется из файла в последнем
коммите шага. Номера оставшихся шагов не меняются: на них ссылаются другие записи.

Пометки:
- **согласовать** — шаг трогает файлы, которые по CLAUDE.md меняются только с согласия владельца
  (`pyproject.toml`, `uv.lock`, `Makefile`, `Dockerfile`, `docker-compose.yml`), или ждёт его решения;
- **ждёт Qn** — нужен ответ на вопрос из [issues.md](issues.md).

## Вне плана

- **Деплой только зелёного `main`.** `main` защищён на GitHub: мерж только через PR с зелёным `check`.
  Остаётся вторая линия — проверка статуса CI в `deploy.sh` перед `git pull`, на случай если защиту
  обойдут или отключат. **Согласовать.**
- **Исправление багов из [issues.md](issues.md)** не входит в рефакторинг, но и не обязано ждать его конца.
- **Пересмотреть обход постов → комментариев → ответов и формат вывода.** Сейчас обход упрощён
  намеренно: на пост — до 100 комментариев верхнего уровня (`count=100`), на комментарий — до 10 ответов
  из ветки (`thread_items_count=10`), остальное не запрашивается. Долгих обсуждений в группе не бывает,
  поэтому лимиты пока не мешают (бывший вопрос Q1, решение владельца). Разобраться вместе с форматом
  вывода: как подписчику видеть ветку, а не поток отдельных сообщений. Это изменение поведения —
  отдельная задача после оценки. Тест на текущий лимит:
  `tests/vk/test_services_feed.py::TestNewReplies::test_replies_are_taken_only_from_thread_items`.
